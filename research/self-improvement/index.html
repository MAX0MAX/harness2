“自我改进”
到底改了什么？

在审阅的实现中，Harness² 用模型修改 agent 周围的配置和工具文件，重跑同一任务，把采用的方案和经验留给未来。它实现了自动改进的流程；是否真的变好，仍是需要实验回答的问题。

01 / 先界定“自己”与“改进”

改的是工作方法、可执行文件和外部经验

MODEL / 模型层

权重保持固定

这条流程调用现成模型做编辑、执行、选择与反思。保存经验不会自动触发梯度更新、SFT 或 RL。

HARNESS / 执行层

修改围绕模型的系统

提示词、技能、脚本、委派角色、插件或 hooks 等。允许修改的具体文件由执行器的 SurfaceSpec 决定。

LIBRARY / 持久化层

把经验交给未来的编辑器

保存“采用的完整 harness + 经验说明”。下一任务在改配置时读这些例子；这条路径没有自动重写框架核心 Python 算法。

因此，Harness² 的定位是：在已有 agent 外面运行的 harness 搜索与经验复用框架。它把人通常会做的“看失败、改规则/脚本、再试一次、总结”编成工作流。外置便于接不同执行器、隔离候选和记录实验；这并不证明同样的机制必须在外层实现，或一定优于直接干预 agent。

依据：recursion.py、library.py、codex.py 的固定版本快照。

def _accept_tree(
    surface,
    adapter: BenchmarkAdapter,
    new: harness_tree.Tree,
    fallback: harness_tree.Tree,
    label: str,
) -> tuple[bool, str]:
    """Repair then validate a proposed tree: (kept_base, "") if accepted, else the error."""
    triggered = harness_tree.autotrigger(surface, new)
    if triggered:
        print(f"  [{label}] auto-triggered skill(s): {', '.join(triggered)}", flush=True)
    changed = harness_tree.diff_summary(surface, fallback, new)
    kept = not (changed["added"] or changed["removed"] or changed["modified"])
    try:
        harness_tree.validate(
            surface,
            new,
            allow_subagents=adapter.spec.allow_subagents,
            reserved_scripts=harness_tree.RESERVED_SCRIPTS | adapter.spec.reserved_scripts,
        )
        adapter.validate_tree(new)
        context.assert_tree_has_no_grader_verdicts(new)
    except ValueError as exc:
        return kept, str(exc)
    return kept, ""

05 / Hermes 已有的部分

“把经验写成技能，以后再用”确实已有实现

在审阅的 Hermes 版本中，常规 agent 可以通过 skill_manage 更新过程性知识，也有回合完成后的后台 memory / skill review。它们是实在的持久化机制，不能把“会保存经验”本身当成 Harness² 独有的创新。

什么时候触发

技能 review 根据工具迭代计数、配置的 nudge 间隔和工具可用性决定；交付完成、未中断且没有禁用后台 review 时才进入后台路径。显式 /refine 也能发起 review。不是每一轮都无条件改技能。

    def _spawn_background_review(self, messages_snapshot: list[dict], review_memory: bool = False,
                                 review_skills: bool = False, focus: Optional[str] = None, explicit: bool = False) -> None:
        """Post-turn review entry point: decide WHEN, then spawn.

        A review whose runtime is the MANAGED LOCAL llama-server is queued for machine idle (``defer: auto``)
        instead of hitting the user's GPU mid-session; everything else spawns immediately. ``explicit``
        (/refine) is never deferred but does not touch the ``focus``-keyed delegate/enabled gates.
        """
        # Gates run at enqueue/spawn time; the idle dispatcher re-checks `enabled` at dispatch time.
        if focus is None and getattr(self, "_delegate_depth", 0) > 0:
            return
        task_cfg = None
        if focus is None:
            from agent.background_review import load_background_review_settings
            enabled, task_cfg = load_background_review_settings()
            if not enabled:
                return

        # Structural clone at the single chokepoint: the fork sanitizes in place, and a shallow copy would
        # alias the live history's nested tool_calls/content.
        # Structural clone at the single chokepoint every review path (automatic, /refine, idle-queue
        # deferral) goes through. See #100795.
        from agent.turn_finalizer import _clone_background_review_messages
        kwargs = dict(messages_snapshot=_clone_background_review_messages(messages_snapshot),
                      review_memory=review_memory, review_skills=review_skills, focus=focus, task_cfg=task_cfg,
                      explicit=explicit)
        if focus is None and not explicit and _review_should_defer(self, task_cfg):
            from agent.review_idle_queue import QUEUE
            QUEUE.enqueue(self, _review_queue_key(self), kwargs)
            return
        self._spawn_background_review_now(**kwargs)

改动怎么保存、以后怎么生效

后台 fork 读取对话快照，继承运行环境，共享 memory store；默认工具白名单限制它通过专门的 skills / memory 工具工作。skill 管理器做结构、路径等校验后写文件。

未来提示词列出技能索引，模型通过 skill_view 加载适用的正文；启用的笔记和用户画像由 system_prompt 构建器注入。当前缓存提示词不会因每次落盘立刻全部重建，生效时机还受会话和重建机制影响。

def selection_pool(
    mode: str, k: int, rollouts: dict[str, RunView], base: Sequence[RunView]
) -> dict[str, RunView]:
    """The one home for selection-pool construction: exactly the k finals of `mode`.

    Labels are derived from k -- agg1..aggk for the parallel mode, c1..ck for the sequential
    one -- so the reference executions are not in the pool and there is no abstention by
    construction. This is the published convention and the only pool this release builds.

    `base` is accepted and deliberately unused: it is what the pool excludes, and the call
    site passes it so that exclusion is visible where the pool is built.
    """
    del base
    labels = (
        [f"agg{i}" for i in range(1, int(k) + 1)]
        if mode == "agg"
        else [f"c{t}" for t in range(1, int(k) + 1)]
    )
    return {lbl: rollouts[lbl] for lbl in labels if lbl in rollouts}

"""Budget accounting: R = 4k rollouts and P = 3k improvement stages.

Base executions count toward each mode. Retries are separate invocation counts;
selection and reflection are recorded outside this ledger.
"""

from __future__ import annotations

from dataclasses import dataclass, field


def expected_rollouts(k: int) -> int:
    """R = 4k: k shared base + 2k candidates + k finals."""
    return 4 * int(k)


def expected_sessions(k: int) -> int:
    """P = 3k: k INV + k DOM + k compositions (parallel: agg1..aggk; sequential: c1..ck)."""
    return 3 * int(k)

08 / 如何继续 challenge

把“会改”与“改得更好”拆成可检验的问题

以下是建议的验证方案，本次未执行这些真实模型实验。固定模型、初始 harness、任务顺序、工具/网络环境，记录总 token、美元成本和耗时；任务由独立评分或可复核测试评判。

A / 和等预算直接干预比

对比单次基线、等预算多次重试并择优、直接加入人工纠正、单 agent 反思，以及完整 Harness²。观察成功率、成本、延迟和退化率。

B / 经验库到底有无增益

同样的任务搜索预算下，比较空库、真实历史库和打乱 domain 的库；只在未参与经验生成的后续任务上衡量迁移。检查是否真的读取与应用过经验。

C / 去掉对照或合成还能否一样好

去掉 Probe、只修基线；或保留 Probe 去掉 Compose。把省下的预算补给其他组，以区分搜索次数与对照证据本身的贡献。

D / 给错误经验一个压力测试

注入看似合理但错误的规则，或改变后续任务事实。测量识别、拒用、修正及负迁移；检查库增长后的上下文与维护成本。

E / 能否可靠地“不改”

放入基础 harness 已正确完成的任务，检验是否徒增规则、强制选出更差产物。额外试验让 baseline 进入选择池的效果；这不是当前发布版默认行为。

F / 改进能否重复出现

对同题、多随机种子重复执行，区分单次巧合与稳定收益；对具体组件做隔离消融，再让独立验证者审阅经验归因。

当前可以下的判断：Harness² 提供了一套可检查、可复现的自动试改与记录机制。要说“比直接干预更有效”或“必须再加一层”，还需要上述控制实验；仅凭“自我改进”的名称、保存了记忆、社区认同或一组平均分，都不足以推出这个结论。
